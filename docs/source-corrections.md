# 批量修正原文

在「阅读设置 → 批量修正原文」中纠正反复出现的 ASR 专名或术语。它只操作当前整篇文字稿的原文，不调用识别、翻译或 AI。

## 核对后应用

1. 输入「查找原文」与「替换为」，明确点击「预览整篇匹配」。只做区分大小写的字面匹配，不使用正则，不做 Unicode 归一化，不跨原片段。
2. 预览显示出现次数与涉及的原片段数，每处都有时间、修改前后与附近文字。默认选择全部，每页 20 处；可逐处选择或取消本页，跨页选择保留。同一原片段的多个命中可以分别取舍。
3. 「应用所选」覆盖整篇所选位置，不受阅读页搜索、说话人筛选或阅读分页影响。修改查找或替换文字会立即废弃旧预览，需要重新核对。
4. 可以将替换文字留空，但不能使任何被修改的原片段成为空白。无匹配、同词替换或没有选择均不写入。

整篇 cue 的身份、顺序、时间、原文及原文基线必须仍与预览一致，否则整批拒绝并要求重新预览。所有所选结果先完成检查，然后一次更新原片段列表，期间新增的笔记、说话人标签、译文等字段保留。

## 保存、失败与撤销

- 每个有变化的片段仅修改 `text`；原先没有 `original_text` 时才保存本批修改前原文，已有原始基线保持不变。时间、来源、媒体、笔记、说话人和阅读位置不改动。
- 页面先显示正在保存，真实存储回执成功才显示已保存。失败时当前修改仍在本页，可「重试保存」或「导出完整 JSON 救援」。重试只保存当前内容，不重复替换。下载后请打开文件确认。
- 本页仅保留最近一批撤销；应用新批次会替换上一批的撤销记录，界面会提示。关闭弹窗后可返回撤销，刷新后不保留撤销记录。
- 撤销回到本批之前的原文和 `original_text` 存在性和值；不会用最初原稿覆盖已有的人工作业，也不会用旧文档覆盖新笔记。如果相关原文已被后续修改或移位，整批撤销拒绝覆盖。
- 应用后立即撤销也走真实保存管线。迟到回执不会重新应用或抢走新页面、弹窗和输入焦点。

## 历史依据与导出

译文、人工核对、摘要、精确/双语摘录及成果集的历史快照不会被改写。依赖修改原文的结果按原有快照规则变为过期；撤销准确恢复依据后可重新为当前。首次修正新加的 `original_text` 也会在撤销时删除，避免精确摘录永远显示过期。

批量应用和撤销会撤销旧模型任务的接收资格，清除未使用的发送同意，停止后续批次。已经发送的请求无法撤回，可能仍消耗额度；迟到结果不会在「应用后立即撤销」时重新写入。再次发送需重新核对并确认。

TXT / SRT / VTT 导出当前修正后的正文；完整 JSON 与书架备份保存正文、初始基线和历史内容，不增加 schema 或无限撤销历史。JSON 恢复后仍可逐段使用原有「恢复原稿」操作，但那不是本批撤销。

## 验证边界

- Node 纯函数与 DOM 回归覆盖 240 cue、多页选择、同 cue 部分命中、Unicode / `$` / 反斜杠字面替换、旧预览、原有基线、单次原子写、失败重试、迟到回执、撤销冲突、JSON/导出与历史依据。
- 注入的四路模型响应覆盖提问、摘要、订阅翻译和离线翻译在途的「应用 → 立即撤销」，不会调用真实模型。
- GitHub Actions 独立真实浏览器场景 `tests/source-corrections-browser.mjs` 使用 authored fixtures、实际 IndexedDB、真实键盘与下载，覆盖 390px / 1360px、44px 控件、完整 focus ring 和五点命中。不会在云工作区启动 Chromium/Electron。
