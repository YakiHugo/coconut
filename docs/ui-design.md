# UI 设计规范

本规范适用于项目的页面结构、交互组件和视觉状态。新增与改动的界面遵循以下约定；存量界面在涉及相应区域的调整时逐步统一。

## 页面结构

页面围绕当前主要任务组织。阅读页优先呈现标题、简短状态与正文；来源详情、处理任务和校准设置通过明确的次级入口进入独立面板或对话框，避免在正文前堆叠工具。

同一区域内区分主要操作、次级操作和状态信息。命名应直接说明结果，例如「新建人工编辑稿」与「AI 整理访谈稿」，让用户在操作前理解区别。

## 界面文案

能由布局、图标、控件状态或交互结果表达的信息，不再增加说明。文案提供用户做决定或完成操作所缺的信息，不重复描述眼前的界面与常见操作。

- 同一页面的标题只出现一次，不在顶部再加无导航作用的标题或面包屑。
- 搜索、关闭、提交等常见操作不常驻展示快捷键，也不通过 `title` 重复标签或解释常识；图标按钮保留必要的无障碍名称。
- 删除装饰性的中英双重标题、重复操作结果的说明和没有下一步价值的成功提示。
- 保留会影响决策的限制、数据发送范围、费用、失败原因与恢复操作，并用最短的准确表述说明。

验收时逐条确认：这句文案补充了什么界面尚未表达的信息？没有补充时删除，信息有必要时优先改进控件命名与交互表达。

## 选择组件

不使用原生 `<select>`，也不通过隐藏原生 `<select>` 驱动自定义外观。

- 少量、需要直接比较的选项使用分段按钮或单选组。
- 较多选项使用项目统一的自定义选择器；需要搜索时提供组合框。
- 自定义选择器沿用统一组件，支持键盘操作、当前值识别、Escape 关闭及关闭后焦点返回。根据实际交互使用正确的语义和 ARIA 状态。

## 激活、焦点与选中状态

元素处于 `:active`、获得焦点或通过 Tab 导航到达时，不在元素外增加一圈 outline、ring、外扩阴影或包围整块区域的选中框。

激活、键盘焦点和选中是不同状态，应分别表达。使用元素内部的背景、文字、图标、下划线或内侧边界变化提供反馈；键盘焦点必须清楚可辨，不能仅移除浏览器默认焦点圈而不提供替代样式。状态变化不应引起布局位移。

## 展示与折叠

除特殊情况，项目中不使用折叠逻辑，包括原生 `<details>/<summary>`、手风琴、可折叠卡片以及自定义「展开／收起」。

简短内容直接展示；不同工作模式使用明确导航或标签页；独立设置与操作使用面板、对话框或独立页面。正文过长时优先改善排版、分节和导航，不默认隐藏内容。

特殊情况例如保留按需查看的大体积原始诊断数据，须在变更说明中写明使用折叠的具体理由，以及常规结构为何不适用。「节省空间」或「次级功能」本身不足以成为例外。当前状态、失败原因与必要的恢复操作应直接可见。

## 界面验收

- 新增与改动区域没有原生 `<select>`。
- 鼠标激活与键盘 Tab 导航均不产生外层选中圈，键盘焦点仍清晰可辨。
- 没有无具体理由的折叠交互，主要内容与必要操作可直接发现。
- 阅读页的辅助工具不挤占正文的主要位置。
