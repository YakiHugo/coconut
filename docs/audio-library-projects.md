# 无文字稿的原声项目

公开 RSS / 单集页或实际音视频直链查到媒体后，可点击「保存原声项目」。保存只写入当前浏览器书架，不下载音视频、不运行语音识别、不下载模型或使用订阅额度。点击「检查本集文字稿」后确认为没有可用定时文字稿的单集，也会保存为原声项目；节目简介不会变成原文。

- 项目包含来源地址、单集标识、媒体地址与类型、可选发布者时长，以及项目笔记和时间书签
- 原声项目明确显示尚无文字稿和摘要。用户笔记不充当原文，摘要、翻译、字幕导出不可用
- 「下载并回听本集原声」是单独操作，最多 200 MiB；播客来源仍按当前 RSS / 页面重新核验。直链沿用公开媒体验证与下载限制
- 可手动添加时间书签，也可从已加载播放器填入当前时间。书签笔记可编辑或删除，定位书签不会自动开始播放
- 来源、笔记与书签保存在当前站点的浏览器书架，刷新后可继续使用；媒体 Blob 不会持久化，刷新或重启后需明确重新获取，或选择对应本地文件
- 单项目 JSON 和整书架 JSON 都保留来源、笔记和书签。JSON 不包含音视频文件；不同来源页面/端口迁移要先导出再导入。Markdown 导出只用于阅读笔记，不能完整恢复
- 重复点击同一来源的「保存原声项目」会打开已有项目，不覆盖笔记；尚未有文字稿时，同时更新重新发现的来源、媒体地址、类型、时长和文字稿状态；已有文字稿保留其核对过的来源。媒体地址或类型变化时清除旧的发布者回听文件并取消旧下载，用户手动选择的本地文件仍保留。导入带不同修改的 JSON 则保留为另一份，整库恢复也不会覆盖不同版本
- 同一来源有多个备份版本时，必须在发现页明确选择目标项目，或选择「单独导入」保留另一份，不会默默选择第一份。
- 后续取得真正的定时文字稿时，可从发现页继续导入到同一个已解析项目，也可在原项目点击「为此项目补充文字稿」选择对应的 JSON / SRT / VTT；可使用高级服务已经完成的 ASR JSON。也可点击「检查并补充发布者文字稿」，重新取得本集明确关联的字幕。原项目标识、用户标题与明确修改过的语言、笔记、书签、收听位置和本次媒体保持连贯，不会另建重复项目。没有文字稿时保持原状，不自动识别
- 补充后，原笔记与书签仍以独立的用户记录显示，原文翻译与摘要只基于真正的文字稿。单项目和整库 JSON、Markdown 笔记导出都保留这些记录；再次保存同一公开来源不会把有文字稿的项目降回原声项目
- 本地文件需由用户核对确实对应当前声音。不会根据标题自动匹配；发布者入口核对准确订阅源、单集标识、媒体地址和类型；媒体变化时先停止，要求重新发现并核对，取消或切换项目后不会写入旧请求的结果

节目/订阅源提供的语言仅作提示。首次附加时优先采用实际文字稿声明的语言；只有用户在项目信息中明确改变过语言时才保留覆盖值，并随 JSON 和刷新保存。只改标题不会生成语言覆盖；明确清空语言会保留用户选择的「未标明」，不会被自动推断覆盖。没有明确覆盖记录的旧项目也优先使用文字稿语言。

发现页已经下载的预览原声在保存项目或导入文字稿时可直接交给阅读器，无需第二次下载。仅在单集、媒体 URL 和类型全部一致、且没有更新的媒体选择时转交；用户手动选的本地文件优先。转交只保留暂停的位置，不自动播放。新发现或预览清理不会撤销阅读器已接管的 Blob URL。详见 [发现页项目连续性](podcast-project-continuity.md)。

每个项目最多保存 100,000 字符项目笔记、2,000 个时间书签、每书签 10,000 字符笔记，全部笔记合计最多 1,000,000 字符。超限导入会拒绝，超限编辑保留修改前内容，不会截断；最大有效项目的 JSON 仍小于 15 MiB 单文件导入上限。保存空间不足或跨页面冲突仍会提示，须导出本页修改后再刷新。已保存的时间不代表已验证媒体内容；实际定位时会检查所选媒体的解码时长。

## 验证

- `npm test` 覆盖项目校验、无伪造原文/摘要、来源保存、重复保存、取消、书签增改删、刷新、单项目导出/导入、整库备份恢复及冲突版本
- `node tests/podcast-browser-acceptance.mjs` 使用原创合成音频与生产 HTTP 路由验证原声项目、显式重新获取、书签定位与 JSON 恢复，无公共网络或模型
- `node tests/podcast-live-browser.mjs` 在授权公共网络验收中使用实际公开音频一次，验证原声项目、笔记、播放时间书签、刷新与干净浏览器导入。真实来源有变化时会失败，不跳过为通过

- `node tests/project-continuity-browser.mjs` 将原声保存、补充文字稿、翻译/摘要请求范围、原声回听、笔记导出、单项目/整库干净浏览器恢复串成一条真实 Chromium 流程。发布者内容与模型响应均为明确注入的测试材料；该测试不能证明真实翻译/摘要质量，也没有运行 ASR

补充文字稿验证完整 JSON（含项目笔记与书签），大型 JSON 使用完整备份审核流程；15 MiB 是 SRT / VTT 字幕导入预算，不会用它截断或拒绝合法完整 JSON 备份。



## 无需文字稿的本地音视频项目

从「添加内容 → 打开本地音视频」选择真实的音频或视频，即可在静态 Web、轻量服务或桌面页面中打开原声项目。无需先取得文字稿、后端、ASR 同意或 AI 工具；不上传、不运行识别、不自动播放。高级「识别本地音视频」仍是另外一个需要明确同意的处理入口。

- 直接创建文件支持的 Blob URL，浏览器按需读取媒体，不会把整段文件读入 JavaScript。没有继承服务端 200 MiB 上传上限；浏览器能否解码取决于实际格式与设备。
- 仅保存文件名、大小、修改时间、MIME 类型、音/视频类别，以及由最多三个 64 KiB 样本与文件元数据生成的候选指纹。前缀检查再读取最多 1 KiB，以拒绝远程播放列表。候选指纹不是完整文件校验，不会证明字幕与原声一致。
- 项目笔记、时间书签、实际解码时长与稳定项目编号保存在书架；没有文件字节、文件路径或 Blob URL。文件需自行保留。默认情况下，刷新、重启、导入 JSON 或移除后撤销都会明确要求重新选择原文件。桌面版可另行选择下述本机引用。
- 同一个文件只有一个候选项目时会重开已有项目，保留标题、笔记、书签和已经补充的文字稿；如果书架含多个同文件备份版本，会列出各版本供选择，不合并、不覆盖不同版本。
- 从项目内重新选择文件时，文件信息和采样内容需与原记录匹配。不同文件会拒绝关联并保留全部笔记；可从「添加内容」另建项目。解码失败会保留项目并提示重新选择。转换后的文件具有不同候选身份，请作为另一份文件打开。
- 正常项目切换保留本页文件 URL 的归属；替换/主动移除媒体及成功移除项目时释放原 URL。删除写入失败时保留原项目和 URL；撤销成功移除不会使用已经释放的媒体。浏览器离开页面时自行释放文档持有的文件 URL。
- 后续点击「为此项目补充文字稿」导入真实 JSON / SRT / VTT，仍在同一项目保存。既有笔记、时间书签、播放器、收听身份保持不变。文字稿文件的无关媒体关联不会覆盖本地原声身份；用户仍需核对内容对应。
- 收听进度使用原有独立记录；重新选中原文件且时长匹配后，「继续收听」只定位，不开始播放。内容 JSON 备份包含手动书签，不把本机独立收听时钟当成跨设备同步记录。

验证：`tests/reader-local-media-projects.test.mjs` 在 Node/HappyDOM 中覆盖真实应用入口、8 GiB 文件的有界读取、失败保存、异步选取/导航/移除竞争、版本选择、刷新、字幕补充和 URL 生命周期。`tests/local-media-projects-browser.mjs` 是仅由 CI 运行的 Chromium 流程，使用原创 PCM 音频、原创字幕与不提供后端能力的静态 HTTP 服务器，验证实际解码、下载与干净浏览器恢复、44px 点击目标和移动端 350px 首段约束。未在此云端工作区启动浏览器或 Electron。


## 桌面版：在这台电脑记住原文件

已成功保存且具有本地文件来源的项目，在「原声与来源」中提供默认不勾选的「在这台电脑记住原文件」。选择真实文件后才可勾选；保存引用失败会明确提示，当前播放器和笔记不受影响。仅 Electron 桌面版与可靠的本机文档数据库支持此选项；静态网页、轻量服务和兼容存储不提供它。播客或后台任务的临时附件不会获得此选项。

- 路径仅写入应用资料目录的小型私有引用清单，不进入文档、书架 JSON、笔记导出或云端；不复制媒体，不扫描文件夹，不请求额外系统权限。数据库私有身份、项目编号、项目生命周期与已保存来源必须全部匹配；导入备份、新建同源版本、移除后撤销或清空数据库均不继承引用。
- 再次打开同一项目时按需载入并保持暂停。不会替换新选择的媒体、展开原声面板、重绘编辑草稿或自动定位。「继续收听 · 仅定位」仍须明确点击，且要求候选身份与解码时长匹配。
- 使用实际文件描述符检查文件身份、大小、高精度修改/变化时间及最多三个 64 KiB 样本；这是有限的候选核对，不是完整文件内容证明。文件被替换、普通原地改写、移走、删除、磁盘断开或无法访问时，保留全部笔记并提示重新选择；不寻找“相似”文件。
- 重新选择移动后的原文件后，可再次明确勾选以更新引用。改名或内容元数据变化仍遵循既有候选指纹规则，不能自动放宽匹配。「不再记住」仅移除引用，不删除文件，也不打断已载入的本次媒体。「移除本次媒体」会阻止本次会话自动重新挂载；随后取消文件选择也不会解除它。明确更换关联文件成功后会取消旧引用，即使两份文件的候选指纹相同；失败保存先保留旧引用，重试保存成功后再取消。旧引用取消失败会明确提示可能的重启行为，并保留“不再记住”重试入口。
- 媒体通过同源不透明会话地址按需流式读取，支持 HEAD 与字节 Range；启动不会完整读取大文件。离开页面、替换附件、移除项目或退出时释放流资源。当前上限为 256 个记住的项目、64 个本次媒体引用；达到上限会提示失败，不静默移除旧记录。

验证：`tests/desktop-local-media.test.mjs` 覆盖原生文件身份、重启清单、写入失败、有界采样、Range/HEAD 和资源释放；`tests/reader-native-media-reference.test.mjs` 覆盖保存/生命周期归属、迟到响应、默认关闭和 JSON 不泄露路径。`tests/desktop-local-media-acceptance.mjs` 在 CI 的真实 macOS 精确 ZIP 上，以原创音频验证原生选择器 → 明确勾选 → 退出/重启 → 实际解码暂停 → 显式续听，以及默认关闭、文件移动/替换、忘记和干净资料目录恢复。仅编写测试不等于该原生验收已运行通过。
