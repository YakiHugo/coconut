# 转录后的 AI 校对

流程为：节目资料与术语 → Qwen 上下文提示 → 原始转录、标点、分句与声纹分组 → LLM 校对 → 修改验证 → 校对稿与待核对项。原始 ASR 检查点始终保留。编辑访谈稿仍是后续独立操作。

支持本机 **Codex CLI** 和 **Kimi Code CLI**。服务使用所在机器上 CLI 的登录和默认模型，不读取浏览器凭据、不上传音视频、不自动切换供应商。Codex 沿用既有 ChatGPT 登录及结构化输出接口；Kimi 使用自定义 `tools: []` / `subagents: []` 文本配置与 `stream-json`，再由程序验证 JSON。Kimi 使用本机已配置的连接，CLI 自身的历史策略仍由其配置决定。

## 新转录自动接续

服务器所有者可在 `.env` 中启用：

```dotenv
COCONUT_TRANSCRIPT_REVIEW_PROVIDER=codex
# 或 kimi；留空时新 ASR 不自动发送 LLM 请求。
# COCONUT_TRANSCRIPT_REVIEW_MODEL=CLI支持的模型ID或别名
```

这表示明确启用新转录的文字校对，会使用所选 CLI 的连接和额度。启动服务、打开书架与普通状态查询不会调用模型。选择在创建来源任务时冻结；重试不悄悄换提供商。Qwen 在识别前接收标题和已确认的人名；校对时还可使用已有节目名单，以及 `transcription_glossary: [{term, source}]` 中有出处的术语。

ASR 完成后，Node 保存 `original-asr.json`，再按完整 cue 分批校对。每批最多 80 个目标句段、约 5,000 字，附前后各两句上下文，整集共享同一份人物/术语资料。只发送原话、时间、已有声音标签与节目资料；笔记、译文、AI 问答和编辑访谈稿不会进入请求。

校对失败不会让已完成的转录消失：来源结果保留可阅读的原稿并记录 `review_status: pending`。导入后可独立校对，已有 ASR 不需要重跑。模型不可用时不自动改用另一个 CLI。

## 已有文字稿

阅读页打开「来源与整理 → 文字整理」，其中的「AI 校对文字稿」区域，可选择 Codex CLI / Kimi CLI 及模型。点击「开始全文校对」才发送任务。任务在服务端持久运行，离开页面不会取消；重新打开面板恢复原任务。取消会终止模型进程，失败、中断或取消后可显式继续，已确认的完整批次不会再次请求。

模型返回有定位依据的 `edits` 和 `issues`，不返回替换整篇的自由改写稿：

```json
{
  "edits": [{
    "cue_id": "segment-9",
    "original": "刘源",
    "replacement": "刘元",
    "category": "entity",
    "basis": "节目标题与嘉宾名单"
  }],
  "issues": []
}
```

## 接收规则

- 只允许修改本批目标 ID；上下文句段不可改。无效 JSON、越界 ID 或不完整批次不会保存为有效检查点。
- 原短语必须唯一匹配，修改不能重叠。实体的正确写法需直接出现在节目标题、简介或有出处的名单/词表中；模型的主观置信度不是依据。
- 标点修改必须保留实词；普通错字仅接受短的等长替换。涉及数字、否定、增删实词、无法可靠映射的词时钟，以及不确定说话人的情况保留为待核对项。
- 允许接收的改字同步投影到逐词文本，保留每个词的原时间；`original_text` 保留最早原识别文字。需要增删实词的建议不会冒充已经对齐，第一版留待回听及后续局部重对齐。
- 现有 cue ID、顺序、起止时间及说话人由程序保持。LLM 不能通过语义自行重分声纹人物。
- 保存前复核原文、时间、说话人与节目资料。期间新增的笔记、译文、编辑访谈稿保留；原文已变则拒绝旧结果。项目删除再恢复后，旧任务不能套到新的项目生命周期。

`transcript_review` 保留输入快照、已接收修改及疑点，provenance 标明提供商和模型。校对稿仍是自动处理结果。疑点按时间在面板分页呈现；模型完成不意味着音频已人工逐句核对。

## 接口与验证

`/api/v1/transcript-review/capabilities`、`/jobs?key=...`、`/jobs/:id` 和 `/jobs/:id/result` 为只读查询。创建任务需 `protocolVersion: 1`、`consent: true`、独立 UUID、文档 key 和当前 `source_signature`，并选择 `provider` / 可选 `model`。`cancel`、`retry`、`apply` 为同源 POST；应用仍经过书架 CAS 和持久回执。前端先通过自己的保存队列提交，服务端幂等确认，避免绕过浏览器的保存身份。

```sh
npm run test:transcript-review
npm run check:reader-ui
```

离线测试覆盖校对边界、原文冲突、词时间投影、按批恢复、取消、删除/恢复隔离、同源协议、CLI 工具限制及浏览器保存。真实 CLI 的公开短样本另行手动验证，不在 CI 消耗账号额度。
