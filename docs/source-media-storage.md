# Durable source media

Source ingestion is separate from transcription. Explicit publisher/video downloads can call `saveSourceMedia(store, key, file, signal)` after creating or selecting the source document. Success means the canonical document was flushed and the media bytes received a durable server receipt. Failures must remain visible and must not be described as saved page blobs.

The canonical library remains SQLite. IndexedDB remains a read-only recovery source. Under the same private library directory, `source-media/` stores SHA-256-addressed media copies and atomic, fsynced JSON receipts. Receipts bind the canonical library namespace, document lifetime, and source identity (`source_url`, `podcast_source`, `media_provenance`, and `local_media_source`). Title, notes, and existing subtitle edits do not invalidate the source attachment. A changed source, deletion/recreation, or another library cannot inherit an old binding. Equal bytes from different providers share the content file, not document ownership.

`POST /api/v1/source-media?key=…&source=…&name=…` receives raw bytes with the normalized media MIME and requires the bridge's same-origin authorization. `source` is SHA-256 of `shared/source-media.js`'s `sourceMediaIdentity(document)`. `GET` at the same endpoint requires `key` and current `source` and returns a media receipt or 404. Content is read from `/api/v1/source-media/content?key=…&binding=…&sha256=…`, supports GET/HEAD/single byte ranges, and verifies the full byte digest before streaming. This path never fetches an upstream URL or invokes ASR.

The `sourceMedia` client capability is explicit and defaults off for old/static readers. When available, reopening a document loads only the local receipt and attaches a local media URL without auto-playing. It does not reconstruct a browser File, redownload the provider media, or start processing. Missing or changed files fail closed; an explicit re-download can repair a corrupt same-hash content file. Media copies are local to the selected library; portable JSON exports still contain source metadata, not these bytes.

Limits: 200 MiB per upload, two concurrent uploads (at most 400 MiB staging), and 2 GiB of committed content. Startup removes only this module's private generated staging files left by an interrupted write. Source removal invalidates playback but conservatively retains media files; automatic garbage collection, a storage-management UI, and cross-computer transfer are not implemented. Keep the complete private library directory for backup/recovery. The production canonical library's exclusive writer owns this asset directory.
